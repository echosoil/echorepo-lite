# Memory-bounded FAPROTAX (R)

The legacy ECHOREPO script `tools/faprotax_16S_functional_profile.R` read file 6
into one dense R data frame (~98,729 OTUs × 2,736 samples), then built
additional full-matrix copies in `microeco`. The process was SIGKILLed
after using about 10.55 GiB RAM.

The revised R script retains the **existing three positional arguments**.
It uses microeco to assign FAPROTAX functions once from taxonomy (with one
synthetic reference sample), then reads file 6 in bounded blocks. Each block
is reduced using a sparse OTU-function × OTU-presence matrix multiplication.
It never keeps the full abundance matrix in RAM. The complete file 6 still
lives on disk; file 7 is small enough to load for taxonomy annotation.

Importantly, the legacy call to `cal_spe_func_perc()` uses
**abundance_weighted = FALSE** by default. So file 8 contains the fraction
of *present OTUs* associated with each function in each sample—not the
fraction of **reads**. The revised script deliberately preserves this
default, reports fractions 0..1 rounded to six decimals (current microeco
defaults), and omits functions with no signal anywhere. File 9 retains the
separate read-weighted annotation-coverage calculation. To change the
scientific interpretation to read-weighted function abundance, do so in a
separately validated analysis.

## Standard use

Run after all 16S biodiversity parts are imported successfully and files
6 and 7 have been generated by the streaming Python preparation step:

```bash
cd ~/ECHO-STORE/echorepo-lite

FAPROTAX_CHUNK_ROWS=128 \
Rscript tools/faprotax_16S_functional_profile.R \
  data/biodiversity/faprotax_work/6_otu_clean_counts_no_blanks.csv \
  data/biodiversity/faprotax_work/7_taxonomy_clean.csv \
  data/biodiversity
```

The output files are unchanged:

- `8_faprotax_samples_x_functions.csv` — fractions for the
  bacterial guild-plot generator
- `9_faprotax_annotated_fraction.csv` — fraction/percent of reads
  belonging to OTUs with at least one FAPROTAX prediction
- `7_taxonomy_NA.csv` — input taxonomy cleaned for prediction

For a smaller memory footprint try `FAPROTAX_CHUNK_ROWS=32`.
For faster parsing if RAM allows, try 256 or 512. The script prints
progress to stderr approximately every 5,000 OTUs. Set
`FAPROTAX_PROGRESS_ROWS=1000` to adjust it.

The script validates the order and identity of every OTU in files 6 and 7;
rejects negative, missing, or non-finite abundances; and writes files 8/9
to temporary files before replacing their final counterparts. A failed
streaming run cannot publish partially computed file 8.

## Verify before publishing

```bash
Rscript tests/test_faprotax_r_streaming.R
```

The tests include a sample dataset with zero-only samples, multiple
functions per OTU, no annotations, various chunk sizes, and a comparison
against the original microeco functional-redundancy calculation when
microeco is installed. They also compare dummy-sample function annotations
with the original full-sample annotation.

After a successful run, use the existing Python image generator:

```bash
BUILD_FAPROTAX_INPUTS=0 GENERATE_FUNGAL_GUILDS=0 \
python3 -u tools/generate_biodiversity_piecharts.py \
  --marker 16S --bacterial-guilds --force
```

No database migration or modification to Python preprocessing is required.
